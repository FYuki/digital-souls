## 続報: 矛盾後の明示訂正

矛盾している一方の値をUIで訂正しても他方だけがCONFLICTEDに残り、
応答で「確定できない」制約が継続する不具合を再現した。
CORRECTでは同じ所有者・属性・形成経路・自己申告区分のCONFLICT関係をたどり、
解決した旧値をSUPERSEDEDにする。各旧値から訂正後の値へCORRECT関係を記録する。
本文・根拠は保持し、別属性、削除済みの知識、一般化との優先関係へ拡張しない。
この処理は削除範囲の拡張とは別であり、保留中の一括削除は実装していない。

3件の矛盾をUI訂正で解決し、無関係な出身地の矛盾は保持する回帰を含む30テスト、
mypy 287ファイル、ruffが成功。実モデル・実UIでのこの追加ケースは未検証。
正式評価は修正前の保存実装を含む`ee0a3ce`で継続中のため、その実行commitと区別する。
訂正で複数の旧値へ関係を張る場合も、再送キーは最初に指定した記憶へ固定する。
対象の対応は結果receiptと同じtransactionで保存し、別の記憶へ同じキーを転用した要求は409となる。
旧版の単一対象receiptは継続して再送できることをHTTP試験で確認した。
