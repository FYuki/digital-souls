実際の会話障害・データ欠損を見つけた場合は、その原因と影響範囲を調べて修正する。

## ユーザーにお願いする実マイク・聴感確認

所要時間は約5〜10分。専用の候補環境と試験用会話を用意し、接続先と固定版を案内してから実施する。
共有dogfoodの実会話・設定を使用せず、試験用の内容だけを話す。

1. ブラウザで音声会話を開始し、マイクを許可する。準備表示が終わってから話せることを確認する。
2. 普通の声で3往復以上話す。例として挨拶、今日やりたいこと、短い質問を使う。
3. 文の途中で少し間を空けてから続きを話す。途中で勝手に応答しないか、最初や最後の言葉が落ちないかを確認する。
4. 返答を聞き、言葉の読み・声の一貫性・文のつなぎ目・音切れ・応答待ちが実用上許容できるか確認する。
5. 返答中に話し掛け直し、旧音声が止まって次の会話へ進めるか確認する。会話終了後に音声が続かないことも確認する。

結果は「問題なし」または症状とおおよその時刻を知らせてもらう。音声のアップロードや会話全文の公開は求めない。
不具合があれば該当する動作を調べる。人の確認が未実施の間は、この必須項目を未確認として残す。
通信断・TTS故障の機械的注入、privacy・履歴・切り戻しはエージェント側の専用試験で確認する。
