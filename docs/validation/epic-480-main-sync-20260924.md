# Epic #480 と通知機能のmain同期

初期基点は引き続き `64a9d60`。6子Issueの実装はEpic `f9c4cc5` へ統合済みであり、各PRの対象headの通常CIが成功した。その後のリモートmain `2f6059b` に追加された通知機能を、専用worktreeで同期した。mainへのマージは行っていない。

## 競合の解消

通知専用起動の分岐はlifespanに残し、必須推論先の接続失敗だけを起動時probeから通知専用起動へ伝える。認証失敗・モデル未存在・設定不備は縮退で隠さない。通知の公開、character確認、終了時の公開state回収は分割後のApplicationRuntime／ToolResourcesへ移した。通知専用起動と通常起動の両方を既存テストで確認した。起動・終了順のテスト用ToolRuntimeも、mainに追加されたnotifications属性と停止後のstate契約に合わせた。

通知、Gate、認可、起動失敗、停止継続の関連161件が成功。Ruffとmypy（386ファイル）が成功。自動マージされたGateの登録済み参照の送信判定とAppの通知表示についても、origin/mainの差分が保持されることを確認した。

main同期後の最新headの通常CI／Container images、実接続再確認、固定条件の前後性能比較、main向けPRのCodeRabbit差分レビューを追跡する。同期前の成功を同期後の成功とは扱わない。TAKT実行時のnative abortは検証専用環境では再現しなかったが、元環境での根本原因は未確定。実マイク・聴感はユーザー担当であり、Codex側の判断待ちとはしない。
