# Epic #151 受け入れ手順

本書は、キャラクター中心の会話画面をmainへ取り込む前に行う自動確認とユーザー確認を定める。
自動テストの成功だけではmainへ取り込まず、最後にユーザーの承認を得る。

## 自動確認

Linux／WSL2上の作業ディレクトリ（例: `~/dev/digital-souls`）にあるリポジトリルートで
次を実行する。`/mnt/c/Users/...`配下はNode.jsの依存関係処理やファイル監視が不安定になるため使用しない。

```text
npm run lint:python
npm run test:unit
npm run test:module
npm run check
npm run build
npm run test:e2e:mocked
```

`frontend/e2e/portrait-layout.spec.ts`は次を検証する。

- PCの初期右配置、背面配置と50%への即時変更、ブラウザ再読み込み後の復元
- tabletの背面固定と100%、mobileの背面固定と50%
- Visual Viewportを844pxから460pxへ縮めた際の入力欄追従と75%設定の維持
- 立ち絵未設定および画像取得404時のプレースホルダーと入力継続

PCとcompactのテストは、Playwright結果へ次のPNGをattachmentとして保存する。

結果と実行環境の関連付けは`frontend/test-results/mocked-e2e/`の
`playwright-results.json`、`resolved-profile.json`、`environment-run.json`、`evidence.json`で確認する。

## ユーザー受け入れ

### PC

1. 1280×800以上で開き、左サイドバーと選択中キャラクターの立ち絵が履歴右側に表示されることを確認する。
2. 設定からPCの立ち絵配置を「会話履歴の背面」へ変更する。
3. PCの履歴範囲を50%、75%、100%へ順に変更し、入力・音声操作を除く会話領域の下端基準で変化することを確認する。
4. 再読み込み後も選んだ配置と割合が復元されることを確認する。
5. サイドバーを閉じ、フローティングのハンバーガーメニューから再展開できることを確認する。

### タブレット

1. 768×1024相当で開き、PC設定にかかわらず立ち絵が履歴背面になることを確認する。
2. ドロワーから設定を開き、タブレット・モバイルの履歴範囲を変更する。
3. スレッド選択後にドロワーが閉じ、会話履歴と入力へ到達できることを確認する。

### モバイル

1. 390×844および320px幅で開き、横スクロールなしでドロワー、スレッド、入力を操作できることを確認する。
2. 履歴範囲を50%、75%、100%へ変更し、背面の立ち絵を確認できることを確認する。
3. 入力欄へfocusしてソフトウェアキーボードを表示し、入力欄がキーボード上端へ追従することを確認する。
4. キーボード表示中も保存済みの履歴割合が一時的に100%へ変わらないことを確認する。

### Epic横断

1. 最初の保存可能な発言で「新しい会話」から自動名へ変わり、手動変更後は上書きされないことを確認する。
2. active／archived一覧の「…」から名称変更、アーカイブ／復元、削除へ到達できることを確認する。
3. キャラクターとスレッドのピン留め、5件折りたたみ、6件以上のピン留め必須表示を確認する。
4. キャラクターを非表示にして再追加し、既存スレッドとピン留めが復元されることを確認する。
5. 立ち絵ファイルを一時的に利用できない状態にし、プレースホルダー表示後もtext／音声操作へ到達できることを確認する。

## 承認境界

子Issueの作業ブランチは必須CI成功後にEpicブランチへ取り込める。EpicブランチからmainへのPRは、
上記の自動確認とユーザー受け入れ結果を提示した後、ユーザーから明示的な承認を得るまでマージしない。
