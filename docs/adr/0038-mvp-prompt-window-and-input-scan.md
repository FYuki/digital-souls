# ADR 0038: MVP の履歴の上限と入力の秘密情報スキャン

Status: Proposed

日付: 2026-10-17

関連: [ADR 0026](0026-prompt-assembly.md)、[ADR 0037](0037-message-level-conversation-history.md)、
[ADR 0005](0005-privacy-boundaries.md)、[ADR 0032](0032-privacy-classifier-evaluation.md)、[privacy ガイド](../privacy.md)

## 背景

現在の組み立て（ADR 0026）は、保存済みの履歴を token 予算に収まるまで古い順に削り、直近 N 往復（`history_floor`、既定3）を下限として残します。
予算が余れば古い履歴もすべて送ります。

privacy は、保存・推論への送信・記憶形成の各境界で、決定論的な scanner とローカルの意味分類器で判定します（ADR 0005）。
分類器（gemma4-12b）は合成60件の評価で各回51/60（85%）の FAIL です（ADR 0032）。

2026-10-17 にユーザーは、MVP について次のとおり決めました。

- 直近 N 往復は上限とする。目的は、長いセッションでの性能の低下を避けること。token 数によるコンパクションでもよい。
- 履歴の上限は「直近 N 件の user の発言と、それに続く応答」とし、既存の token 予算による削減と併用する。要約によるコンパクションは後続（推奨案で可）。
- 応答は SSE で返すため、応答の判定はしない。
- クラウドの LLM を使う可能性があるため、入力の判定だけ残す。判定は秘密情報のスキャナーだけにする。
- 判定の目的は、外部の LLM へ送らないことと、応答で話さないことの両方。
- 入力で検出したら LLM に渡さず、定型の応答を返す。発言は保存する（推奨案で可）。

## 選択肢

履歴の上限：

| 案 | 判断 |
| --- | --- |
| token 予算だけ（現状。N は下限） | 不採用。予算が余る限り古い履歴をすべて送る |
| 直近 N 件の user の発言とその応答を上限にし、token 予算と併用する | 採用を提案 |
| LLM の要約によるコンパクション | 後続。LLM の呼び出しと品質の評価が増える |

入力の判定：

| 案 | 判断 |
| --- | --- |
| 判定しない（プロバイダーに任せる） | 不採用。プロバイダーは入力の個人情報を除かない。誤って貼った秘密情報が外部に残る |
| 決定論的な秘密情報のスキャナーだけ | 採用（ユーザー決定） |
| スキャナーとローカルの意味分類器 | 不採用（MVP）。分類器は品質 FAIL で、往復ごとの推論が増える |
| 応答の判定 | 不採用。SSE の逐次表示と両立しない |

## 決定（提案）

### 1. 履歴の上限

- 組み立てに入れる履歴は、直近 N 件の user の発言と、それぞれに続く assistant の発言までにします。それより古い発言は送りません。
- その範囲の中で、ADR 0026 の token 予算による削減を従来どおり適用します。
- N は運用の設定にします。初期値は実測で決め、決めるまでは20を仮の値にします（AI の提案、未検証）。
- 保存済みの履歴は削りません。上限は送る範囲だけに適用します。
- 長期記憶の検索結果（記憶の領域）は MVP では入れません。

### 2. 入力の秘密情報スキャン

- 応答を生成する前に、まだ応答していない user の発言（[ADR 0037](0037-message-level-conversation-history.md) §2）を、
  既存の決定論的なスキャナー（`privacy_scan`、[privacy ガイド](../privacy.md#検出範囲と限界)）で検査します。
- 秘密情報を検出したら LLM を呼ばず、定型の応答を SSE で返します。定型の応答は本文に検出した値を含めません。
- 検出した発言は会話履歴には保存したままにし、以後の組み立てには入れません（スキャンの結果を発言に記録します）。
  定型の応答も、組み立てには入れません。
- スキャンに失敗した場合は、検出した場合と同じ扱いにします（fail-closed）。
- スキャンは推論先がローカルかクラウドかを問わず適用します。
- ローカルの意味分類器は、応答の経路では使いません。長期記憶の形成での判定（ADR 0005・0017）は変えません。

### 3. 応答の判定はしない

応答は SSE で逐次返し、返す前の判定はしません。「応答で話さない」ことは、仕組みでは保証しません。
人格の組み立てでの指示と、ユーザーによる会話の削除で対応します。

## 置き換える決定

承認された時点で、次に置換の注記を付けます（本文は書き換えません）。

- [ADR 0026](0026-prompt-assembly.md)：履歴の直近 N 往復を下限だけとする扱い（上限を追加する）。
- [ADR 0005](0005-privacy-boundaries.md)：推論への送信の前の意味分類器による判定（応答の経路では scanner だけにする）。

## 影響

- スキャナーは網羅的ではありません。秘密情報の一部や、健康・家族など機微な情報は外部の LLM へ送られます。
  クラウドの推論先を使う場合は、その契約の学習への利用・保持期間を運用者が確認します。
- 応答で機微な情報を話すことは防げません。
- 往復ごとのローカル推論がなくなり、応答までの時間が短くなります。
