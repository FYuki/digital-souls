# ADR 0036: MVP の認証（Core が発行する key）と利用者

Status: Proposed

日付: 2026-10-17

関連: [ADR 0035](0035-mvp-client-structure.md)、[ADR 0004](0004-conversation-history.md)、
[Epic #217](https://github.com/FYuki/digital-souls-core/issues/217)、[Issue #77](https://github.com/FYuki/digital-souls-core/issues/77)

## 背景

現在の Core は、利用者の区別（subject・client・audience）をサーバー側で固定しています
（local-operator / local / local-private。[推論 API](../api.md#文脈プライバシー)）。
呼び出し側からの指定は拒否し、認証はありません。そのため、どのクライアントからつないでも同じ利用者になり、
CLI の履歴を分けることも、PC の外からの接続を守ることもできません。

2026-10-17 にユーザーは、MVP の認証を「バックエンドが発行した key を登録する簡易なもの」とし、
Web とネイティブは履歴を共通に、CLI は別にすると決めました。
これより前（2026-10-13）に、同じ PC からの接続にもトークンを必須にすると決めています（Epic #217 の前提）。

Epic #217 は、役割（管理者・配信・ジョブ）ごとの権限を含む認証を、#77 の対応の後に行う計画です。

## 選択肢

| 案 | 判断 |
| --- | --- |
| 認証なし（現状） | 不採用。同じ PC でもトークン必須の決定に反し、CLI の履歴を分けられない |
| Core が発行する key（Bearer）で利用者を決める | 採用を提案 |
| 利用者の登録・ログイン・OAuth | 不採用。単独の利用者には過大（Epic #217 でも作らない） |

## 決定（提案）

### 1. key の発行と保存

- key は、Core を動かしている PC で、管理者がコマンドで発行します。HTTP からは発行できません。
- 発行時に、key を対応づける利用者（例：`owner`、`cli-test`）と、用途のラベル（例：`web`、`native`、`cli`）を指定します。
- key は十分な長さの乱数です。発行したときに一度だけ表示し、Core はハッシュ値だけを保存します。
- key は失効させられます。失効した key は次の要求から使えません。
- key をログ、エラー、証跡に出しません。

### 2. 要求の認証

- クライアントは `Authorization: Bearer <key>` を付けます。同じ PC からの接続でも必須です。
- key がない、形式が違う、未知、失効済みの場合は 401 にし、処理を始めません。どの理由で失敗したかは区別して返しません。
- 認証に通った key から利用者を決め、その利用者を会話履歴の境界（Binding の subject）にします。
  呼び出し側の JSON やヘッダーで利用者を指定することは引き続き拒否します。

### 3. 利用者と履歴の範囲

- MVP の Binding は「利用者 × キャラクター」です。用途のラベル（web・native・cli）は記録しますが、Binding には含めません。
  このため、同じ利用者に対応づけた Web と ネイティブの key は、同じ会話の一覧を使います。
- CLI は別の利用者（例：`cli-test`）の key を使い、履歴を分けます。
- 利用者ごとに履歴が分かれる以外の権限の差は、MVP では設けません（1つの役割だけ）。

### 4. Epic #217 との関係

この ADR は Epic #217 の一部（key の発行・ハッシュでの保存・失効・トークン必須）を先に行うものです。
役割ごとの権限、配信の視聴者の識別、Cloudflare Access の検証は Epic #217 に残します。
Epic #217 を「#77 の後」とした順序は、2026-10-17 のユーザー回答（「順序を入れ替えて良い」）で入れ替えます。

## 置き換える決定

承認された時点で、次に置換の注記を付けます（本文は書き換えません）。

- [推論 API](../api.md#文脈プライバシー) の「scope はサーバー固定」の記述。
- [ADR 0004](0004-conversation-history.md) の「localhost の単一利用者限定で、認証ではない」の記述。

## 影響

- すべての API に key が必要になります。評価のハーネスやテストは key を使うよう変更が必要です。
- 利用者の区別が変わるため、既存の履歴（固定 scope）は新しい利用者へ移しません（[ADR 0037](0037-message-level-conversation-history.md)）。
