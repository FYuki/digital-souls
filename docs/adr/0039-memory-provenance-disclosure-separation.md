# ADR 0039: 記憶の出典情報・開示区分・参照の文脈を分け、場に応じて参照可否を判定する

Status: Proposed

日付: 2026-10-18

関連: [ADR 0004](0004-conversation-history.md)、[ADR 0016](0016-memory-kinds-and-records.md)、
[ADR 0017](0017-memory-formation-admission.md)、[ADR 0018](0018-memory-retrieval-context.md)、
[ADR 0019](0019-memory-correction-invalidation.md)、[ADR 0020](0020-reflection-personality-relationship.md)、
[ADR 0022](0022-memory-retrieval-from-records.md)、
[Issue #77](https://github.com/FYuki/digital-souls-core/issues/77)。
未統合の提案として ADR 0034（記憶の共有と名前の置き換え、branch `docs/214-memory-sharing-adr`）と
ADR 0036・0037（[PR #222](https://github.com/FYuki/digital-souls-core/pull/222)）を参照します。

## 背景

現行の記憶は、Binding（subject・client・audience・character の組）の完全一致だけで所有と参照を決めています
（[ADR 0004](0004-conversation-history.md)、[ADR 0022 §1](0022-memory-retrieval-from-records.md#1-候補元と有効性u1u2)）。
一方で次の提案・要求が、この1つの値では表せない区別を求めています。

- ADR 0036（Proposed）は、会話履歴の Binding を「利用者 × キャラクター」にします。
- ADR 0034（Proposed）は、Episode・Semantic を利用者をまたいで共有し、訂正は利用者単位、照合はキャラクター単位とします。
- ユーザーは、配信とグループチャットの場でキャラクターが記憶を使うことを求めています。

参照できるかどうかを Binding の一致だけで決めると、非公開の場で聞いた話を公開の場で話す、
あるいは私的な会話から育った興味を公開の場で一切話せない、のどちらかに偏ります。

## 選択肢

| 案 | 内容 | 判断 |
| --- | --- | --- |
| A：出典だけで判定 | 元の場の公開度で参照範囲を決める（YonerAI 型） | 私的な場から育った興味や一般的な話題まで公開の場で使えなくなる（D7 に反する） |
| B：出典と内容の両方で判定 | 出典の公開度は、人・会話を特定し得る内容にだけ効かせる | **採用** |
| C：内容だけで判定 | 内容が安全なら出典を問わない | 「誰がいつ話したか」による漏えいを防げない |

## 決定（提案）

### 1. 三つの軸

| 軸 | 内容 | 決まる時点 | 用途 |
| --- | --- | --- | --- |
| 出典情報（provenance） | 話者・場・発言時点の公開度・出典アドレス | 発言時点で固定し、書き換えない | 失効、根拠の独立性の計数、開示判定の入力 |
| 開示区分（disclosure class） | その記憶の内容が誰（何）を特定し得るか | 形成時に判定し、判定器の version を記録する。再判定できる | 開示判定の入力 |
| 参照の文脈（access context） | キャラクター・参照者・今の場・場の公開度・`broadcast`・目的（会話・会話外の活動・整理） | 参照のたびに決まる | 開示判定の入力 |

会話履歴の所有は ADR 0036 の「利用者 × キャラクター」のままとします。
記憶の所有はキャラクターとし、利用者・場は出典情報として持ちます。
他の利用者に由来する記憶を参照できるかは §6 の判定で決め、所有の境界では決めません。
別のキャラクターの記憶は、どの段階でも参照・照合・形成の入力にしません。

### 2. 出典情報

| 項目 | 内容 | 置き場所 |
| --- | --- | --- |
| 話者 | 利用者、または assistant | Citation |
| 場 | 入口の種類（web・native・cli・discord_dm・discord_channel・配信 等）と場の ID | 出典（SourceVersion） |
| 発言時点の公開度 | `ONE_TO_ONE` / `CLOSED_GROUP` / `PUBLIC`（§3） | 出典 |
| `broadcast` | 発言時点で配信の場だったか | 出典 |
| 出典アドレス | 会話・発言の位置・epoch（ADR 0037 を採用する場合は会話 ID ＋ seq） | 出典 |

公開度と `broadcast` は、Core の設定とアクセス元（adapter）の設定で決めます。LLM には決めさせません。
発言時点の公開度が不明な出典は `ONE_TO_ONE` として扱います（最も狭い）。

### 3. 場の公開度

| 公開度 | 例 | 場にいる人 |
| --- | --- | --- |
| `ONE_TO_ONE` | Web・ネイティブ・CLI・Discord DM | 利用者本人とキャラクター |
| `CLOSED_GROUP` | 招待制のグループ、閲覧者を限定した channel | 限られたメンバー |
| `PUBLIC` | 誰でも見られる channel・配信 | 不特定 |

公開度と `broadcast` はアクセス元（adapter）が自動で判定し、運用者が場ごとに Core へ登録した値で上書きできます（D16）。
例えば Discord channel は `@everyone` から見えるかで `PUBLIC` かを、配信のコメント入口は常に `broadcast` を判定します。
アクセス元が申告できる場の種類は、Core の設定で許したものに限ります。判定できない場合は下の「不明」の扱いにします。

`broadcast` は公開度とは別の属性で、不特定の相手に届き、記録として残る場を表します。
配信の場は `PUBLIC` かつ `broadcast` です。今の場の公開度が不明な場合は `PUBLIC` かつ `broadcast` として扱います（最も広い）。

### 4. 開示区分

| 区分 | 例 | 出典の公開度で制限するか |
| --- | --- | --- |
| `CHARACTER_SELF` | キャラクター自身の興味・好み・人格・感想 | しない |
| `GENERAL` | 誰も特定しない話題・知識（「新作の Y が公開された」） | しない |
| `ABOUT_SPEAKER` | 話者本人の情報（「ユーザーはラーメンが好き」） | する |
| `ABOUT_THIRD_PARTY` | 第三者の情報 | する。加えて ADR 0034 の名前の置き換え・共有規則に従う |
| `ABOUT_CONVERSATION` | その会話・場であったこと自体（「A さんとこう話した」） | する |

境目は雑談かどうかではなく、人や会話を特定し得るかどうかです。
区分を判定できない場合は `ABOUT_SPEAKER` として扱います（D10）。
機微情報は区分の対象ではなく、保存判定で拒否します（[ADR 0017 §2](0017-memory-formation-admission.md#2-型付きの保存判定)）。

区分は記録ごとに付けます。Episode は通常 `ABOUT_CONVERSATION` で、添付する Fact は内容に応じて
`GENERAL` 等になり得ます。区分の判定は保存判定と同じく、判定の由来（分類器・モデル・prompt・policy の version）を記録します。

### 5. キャラクター視点への射影

`ABOUT_CONVERSATION` と `ABOUT_THIRD_PARTY` の記録は、人を省いたキャラクター視点の文（射影）を持てます（D9）。

- 5W の行為者・相手を「誰か」「みんな」等へ一般化し、場と具体的な日時を除きます。キャラクターが何をしたか・どう感じたかは残します。
- 射影した後の内容を改めて区分判定し、`CHARACTER_SELF` または `GENERAL` になった場合だけ射影を有効にします。
  相手の状態・行動が中心の経験（例：落ち込んでいた相手の話を聞いた）は、人を省いても話者の情報が残るため使いません。
- 射影は形成側で作り、元の記録の派生として保存します。人名等の残存は ADR 0034 の決定論的な検査と同じ方式で確認し、残れば射影を作りません。
  応答時に prompt で「人を省いて話す」よう指示する方式にはしません（prompt は強制機構ではないため）。
- 射影は元の記録の失効に従って即時に利用停止します（[ADR 0019 §4](0019-memory-correction-invalidation.md#4-失効invalidation)）。

### 6. 参照可否の判定

入力は記録の出典情報・開示区分と参照の文脈です。結果は `ALLOW_FULL`・`ALLOW_PROJECTED`・`DENY` と理由コードで、
理由と記録の参照（ID）だけを記録し、本文・query は記録しません。上の規則から順に適用します。

1. キャラクター不一致、失効・停止、出典の不適格 → `DENY`（既存の規則）
2. 区分が `CHARACTER_SELF` または `GENERAL` → 出典を問わず `ALLOW_FULL`
3. 今の場が `broadcast` → `ABOUT_SPEAKER` は `DENY`（D11）。`ABOUT_CONVERSATION`・`ABOUT_THIRD_PARTY` は有効な射影があれば `ALLOW_PROJECTED`、なければ `DENY`。配信の場で得た記録も話者を出さず、射影だけを使う
4. 記録の元の場と今の場が同じ → `ALLOW_FULL`（その場にいる人には元々見えている内容のため）。
   発言者の名前を出してよく（D13）、参照者が後から参加した人でも同じです（D14）。場を離れた人は今の場にいないため対象になりません
5. 参照者が話者本人で、今の場の公開範囲が元の場の公開範囲に含まれる → `ALLOW_FULL`。
   `ONE_TO_ONE` 由来は、本人の `ONE_TO_ONE` の場であれば入口をまたいで参照できる（D4）
6. 上記以外（他の利用者に由来し、別の場） → ADR 0034 の共有規則。規則が定まるまでは `DENY`

判定は検索の候補を絞る段階と、推論の送信直前の再検証（`GuardedContext.valid()`）の両方で行います。
`broadcast` の場への送信は、[ADR 0020 §6](0020-reflection-personality-relationship.md#6-会話外の活動との境界)の流出防止ゲートで出力を再判定します。

### 7. 形成での出典の扱い

- 一般化・内省・興味・人格の形成の入力は、場を問わず、同じキャラクターの記録全体です（D8）。
- 出典を使うのは、根拠の独立性の計数（同じ元発言からの記録を二重に数えない、[ADR 0016 §5](0016-memory-kinds-and-records.md#5-出典版識別子)）と、
  失効の系譜（根拠が削除されたら派生結果を再評価する）だけです。
- 派生結果の開示区分は、出典から引き継がず、派生した内容そのものを判定します。
  複数の安全な経験から機微な内容を推論し得るため、privacy も再評価します（[ADR 0020 §2](0020-reflection-personality-relationship.md#2-reflection)）。
- 派生結果の根拠を説明する場合も、根拠の記録はそれぞれの区分と §6 の判定に従います（射影があれば射影で答える）。

### 8. 配信の場の記憶の単位

Kizuna を参考に、配信の場では内容の記憶と関係の状態を分けます（D15）。以下は AI 提案です。

| 単位 | 内容 | 開示 |
| --- | --- | --- |
| 場 × キャラクターの集約 Episode | 「この配信でこんな話題で盛り上がった」等の、配信の場で起きたこと。視聴者ごとには作らない | §5 の射影だけを使う |
| 視聴者ごとの関係の状態 | 段階・温かさ・継続・傷。発言本文や内容の記憶は持たない | その視聴者へ応答するときだけ、口調・距離感の文脈として使う。数値はモデルへ渡さず自然言語へ変換する |

- 関係の状態の更新は決定論的に行い、LLM は反応の感情（valence）を返すだけにします。重大な違反の判定は moderation 等のアプリケーション規則で行います。
  [ADR 0020 §4](0020-reflection-personality-relationship.md#4-temperament-と-personality) の「LLM に数値の delta を自由に決めさせない」と同じ考え方です。
- 接触の履歴には種別・valence・時刻・期間の区切りだけを残し、発言本文は残しません。傷の内容も自由文ではなく型付きの分類で持ちます。
- 視聴者は配信サービスの ID を不透明な値として扱い、Core の利用者と紐付けていない視聴者は場（サービス）ごとの別人とします。
  視聴者から忘れるよう求められた場合や、運用者の操作で、その視聴者の関係の状態を削除できるようにします。
- Kizuna は TypeScript のため依存として取り込まず、判断は Core が持つ方針に従い、規則を参考に Core 側で実装します。

## 影響

- [ADR 0016](0016-memory-kinds-and-records.md)：出典に場・公開度・`broadcast` を、記録に開示区分と判定の由来を、射影を派生の記録として追加します。
- [ADR 0017](0017-memory-formation-admission.md)：形成で開示区分の判定と射影の生成を行います。§5 の Fact 照合範囲（同一スレッド）は ADR 0034 の「照合はキャラクター単位」と合わせて見直します。
- [ADR 0018](0018-memory-retrieval-context.md)・[ADR 0022](0022-memory-retrieval-from-records.md)：検索候補を §6 で絞ります。
  Episode を参照できない場でも `GENERAL` の Fact を使えるよう、Fact を独立した候補にできるようにします。
- [ADR 0019](0019-memory-correction-invalidation.md)：射影と区分の判定結果も失効の対象にします。
- ADR 0034・0036・0037（Proposed）：本 ADR の軸に合わせて読み替えます。会話履歴の境界（利用者 × キャラクター）は変えません。
- MVP（Web・ネイティブ・CLI の1対1）では規則 4・5 で本人の記録だけを参照します。
  出典の場・公開度と開示区分は MVP の時点から保存し、後から schema を作り直さないようにします。

## 実施順（提案）

1. MVP：1対1の場。出典の場・公開度、開示区分の保存と §6 の判定
2. 配信：`broadcast` の場、射影、配信の場での集約 Episode の形成、流出防止ゲート
3. グループチャット：`CLOSED_GROUP`、他の参加者の保存への同意、複数話者の帰属
