# ADR 0019: 記憶の訂正・時間変化・矛盾・削除と失効

Status: Accepted

一部を[ADR 0021](0021-postgresql-only-storage.md)のPostgreSQL一本化で置き換えます（往復削除をSQLiteでも物理削除する記述。PostgreSQLでの物理削除と往復削除の規則は維持）。

日付: 2026-10-06

Accepted日: 2026-10-07

根拠: 2026-10-06のユーザー決定（[SPEC §4.1の決定表](../../SPEC.md#41-決定済み2026-10-06のユーザー決定)）と
[PR #67](https://github.com/FYuki/digital-souls-core/pull/67)のレビュー。

## 背景

現行Coreは、会話履歴の削除・プライベートモード化による出典の撤回と、残る出典からの再構成を実装しています
（[ADR 0006](0006-conversation-memory-controls.md)、[ADR 0007](0007-memory-provenance-and-revocation.md)）。
一方、知識の訂正と時間変化の区別、矛盾の保留、管理操作による訂正・削除、依存する派生結果の失効は
ありません。[ADR 0015](0015-memory-model-reorganization.md)に従い、PoCの
[意味記憶の訂正・時間変化・矛盾](https://github.com/FYuki/digital-souls-poc/blob/fce7382884d981c42be7fbd3ddaffe7469e27588/docs/decisions/semantic-memory-lifecycle-2026-09.md)と
[Episode・Fact・Semantic境界](https://github.com/FYuki/digital-souls-poc/blob/fce7382884d981c42be7fbd3ddaffe7469e27588/docs/decisions/episode-fact-semantic-boundaries-2026-09.md)第9節を採用します。

## 決定

### 1. 知識の適用範囲

スレッドは増分抽出の枠に限ります。知識の照合・参照・訂正は、同じBinding全体へ適用します。
スレッドごとに知識を分離すると、別スレッドで訂正・想起できないためです。

### 2. 訂正と時間変化

- 明示的な訂正（「間違えた、実は〜」）は旧知識の訂正として追跡する。
- それ以外の食い違いは原則として時間変化とし、旧状態を履歴として保持する。
  適用日時が不明な場合は補完しない。
- 誕生日など通常変化しない属性の食い違いは矛盾として保留し、どちらも確定して断定しない。
- 自己申告と経験からの一般化が食い違う場合は共存させ、会話では自己申告を優先する。
  矛盾だけでは一般化を無効にしない。
- 未解決の矛盾は後続の内省から参照できるようにする。質問や主観の表出はこの範囲に含めない。

適用時期と保存時刻を区別し、訂正・時間変化・矛盾の関係を追跡します。

### 3. 管理操作

| 操作 | 範囲 | 扱い |
| --- | --- | --- |
| 本文の訂正 | ユーザー自己申告に由来するSemanticと、Fact単位 | 元発言を書き換えず、管理操作による訂正として根拠・版を追跡する |
| 削除 | すべての形成経路のSemantic、Episode、Fact | 元会話・Episodeの削除とは別の操作。同じ出典・版からの再生成を防ぎ、新しい根拠からの取得は許可する |

削除の再処理防止には、本文を残さない最小の識別情報だけを保持します。削除済み本文を監査目的で保持し続けません。
管理操作も正本の共通の保存・版・privacy・失効契約を通し、管理専用の正本を作りません。
候補ごとの手動承認や手動のFact統合は追加しません。

### 4. 失効（Invalidation）

根拠となるEpisode・Fact・source・統合関係の訂正・削除・版の失効時は、次を適用します。

- 依存する統合関係、Semantic、Reflection、派生結果を、正本上で即時に利用停止し、再評価の対象にする。
- 他の出典が残っていても、旧統合・旧本文を無条件に有効のままにしない。残る根拠から再評価する。
- 登録・参照更新・統合関係・派生index予定を原子的に整合させ、適用直前に版を検証する。
- 循環、複数の有効な統合先、別Bindingへの参照を拒否し、再試行・並行処理で二重に統合しない。
- 派生indexの削除・再生成が遅れても、取得時に正本で有効性を再確認する。
- 旧ID、統合履歴、別の参照、checkpointから、削除・無効化した情報を復活させない。
- 人格全体を無条件に過去へrollbackせず、影響する特性と残る根拠から再評価する（[ADR 0020](0020-reflection-personality-relationship.md)）。

### 5. Coreの操作仕様との関係

[ADR 0006](0006-conversation-memory-controls.md)のユーザー指定の操作仕様を優先します。

- 会話履歴の削除では、そこから作られた記憶も削除します（PoCの「履歴削除と記憶の物理削除は別操作」より厳しい）。
- スレッドのプライベートモード化では、そのスレッド由来の既存記憶を削除し、解除しても自動で復活させません。
- 複数sourceの記憶で一部のsourceが撤回された場合は、旧記憶を直ちに利用停止し、残る適格sourceから再構成します。
- アーカイブは記憶を維持します。

Episode・Fact・Semanticが加わっても、これらの操作は出典を共有するすべての記録と派生結果へ同じく適用します。

話を聞いた別のEpisodeまで無条件に物理削除はしませんが、削除対象の情報が本文に残る場合は停止・再評価します。

### 6. 保存への同意（2026-10-06のユーザー決定）

長期記憶の登録を有効にした状態で会話したことを、保存への同意として扱います。候補ごとの確認は行いません
（[ADR 0017](0017-memory-formation-admission.md)）。製品として配布・販売する場合は、初回の画面で
プライバシーポリシーの提示と同意の取得を行います。

### 7. 保存拒否の語と、履歴の削除（2026-10-06のユーザー決定）

1つのスレッドを長く使う利用を前提にします。

- 「覚えないで」「記録しないで」等の自然文から、保存範囲を自動で推測・適用しません。
  Coreは現在のuser発言を決定論的scanner（既存の`no_history`・`no_memory`判定）で検査し、語を検出したら
  応答と一緒に確認を求める信号を返します。assistantの引用・説明は保存拒否の指示として扱いません。
- 語を検出した発話は、確認が取れるまで記憶形成の対象外として保留します。
  プライベートモードへの切替をユーザーが確認したら、既存の明示API（[ADR 0006](0006-conversation-memory-controls.md)）で
  切り替えます。切替を断った場合だけ、保留した発話を通常の形成対象へ戻します。応答がない間は対象外のままです。
- AIの判断では会話履歴を削除しません。AIはプライベートモードと履歴の削除機能を案内するだけで、
  実行はユーザーが行います。
- 会話履歴の削除機能では、削除する範囲をユーザーが選べるようにします。会話全体に加えて、
  会話往復（user入力と、それに対するassistantの応答・tool往復）単位の削除を追加し、
  「選択した往復だけ」と「選択した往復以降すべて」を選べるようにします。

会話往復単位の削除は次を満たします。

- 削除した往復を出典に持つ記憶を撤回し、複数の出典を持つ記憶は残る出典から再構成します（6節までの規則を往復単位へ拡張）。
- 「選択した往復だけ」を削除した場合も、それより後の往復は引き続き記憶の対象とします（2026-10-06のユーザー決定）。
  後続の応答を対象外にすると、削除を一度でも行ったスレッドが以後の記憶に使えなくなるためです。
  後続の往復も消したい場合は、ユーザーが削除範囲を選んで削除します。
- tool callと結果が往復をまたぐ場合は、対応する往復をまとめて削除対象にします。
- 本文を持たない削除済みの印を残し、同じrequest IDの再送で内容を復活させません。
- 削除も会話のrevisionを進め、進行中の推論のcommitを拒否します。SQLite・PostgreSQLの両方で物理削除します。

## 影響

- 正本に、訂正・時間変化・矛盾の関係、適用時期、削除の再処理防止の識別情報を追加します。
- 現行の撤回イベントとepoch（ADR 0007）を、Episode・Fact・Semantic・Reflectionへの依存にも拡張します。
