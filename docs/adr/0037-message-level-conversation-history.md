# ADR 0037: 会話履歴を発言単位で保存する

Status: Proposed

日付: 2026-10-17

関連: [ADR 0035](0035-mvp-client-structure.md)、[ADR 0036](0036-mvp-api-keys-and-users.md)、
[ADR 0038](0038-mvp-prompt-window-and-input-scan.md)、[ADR 0004](0004-conversation-history.md)、
[ADR 0005](0005-privacy-boundaries.md)、[ADR 0006](0006-conversation-memory-controls.md)、
[ADR 0007](0007-memory-provenance-and-revocation.md)、[ADR 0019](0019-memory-correction-invalidation.md)

## 背景

現在の会話履歴（ADR 0004、[履歴 API](../history-api.md)）は、user の入力と assistant の応答を1往復としてまとめて保存します。
request ID と期待 revision で排他し、保存の policy が許可しない場合は保存しません（既定は拒否、ADR 0005）。
プライベートモード・発話の除外（ADR 0006）、保存拒否の語の確認、往復単位の削除（ADR 0019）もあります。
通常の起動ではこの経路は無効で、trusted な Python のコードで保存先と policy を注入したときだけ使えます。

2026-10-17 にユーザーは、MVP について次のとおり決めました。

- 会話履歴としては判定せずに保存する。
- 会話履歴を削除したときは、長期記憶用のデータも削除する（同じテーブルでもよい）。
- 応答の組にせず、順序の情報だけを持つ（連投に対応するため）。
- 連投は、まだ応答していない user の発言をまとめて1回の応答にする。応答の生成中に届いた発言は、次の応答で扱う（推奨案で可）。
- プライベートモードと保存拒否の語の検出は外す。会話履歴・会話の削除はユーザーの操作で行う。
- 会話は複数持てる。既定では最後にやり取りした会話を再開する。

## 選択肢

| 案 | 判断 |
| --- | --- |
| 往復単位の保存（現状）を拡張する | 不採用。連投を往復にまとめられず、判定しない保存と既定拒否の policy が両立しない |
| 発言単位で、会話内の連番と一緒に保存する | 採用を提案 |

## 決定（提案）

### 1. 保存の単位

- 会話（conversation）は Binding（[ADR 0036](0036-mvp-api-keys-and-users.md) の利用者 × キャラクター）に属し、
  作成日時と最終活動日時（最後に発言を保存した日時）を持ちます。
- 発言（message）は会話の中の連番（seq）を持ち、role（user / assistant）、本文、保存日時を持ちます。
  assistant の発言には、組み立てに使った Card のハッシュを持たせます（[ADR 0029 §6](0029-persona-consistency-evaluation.md#6-card-のハッシュ)）。
- 往復の組・revision・receipt は持ちません。発言の順序は seq だけで表します。
- 保存の前に privacy の判定をしません。会話履歴としてはすべて保存します。
  秘密情報のスキャンはプロンプトの組み立ての側で行います（[ADR 0038](0038-mvp-prompt-window-and-input-scan.md)）。
- ツールの呼び出しと結果は MVP の範囲外です。

### 2. 発言の送信と応答

- user の発言の保存と、応答の生成を分けます。
  - 発言の保存：クライアントが付けた ID で重複を除き、届いた順に seq を付けて保存します。応答の生成を待ちません。
  - 応答の生成：その時点で最後の assistant の発言より後にある user の発言をすべてまとめて受け、1回の応答を SSE で返します。
- 1つの会話で同時に生成する応答は1つだけです。生成中に応答の要求が来たら 409 にします。
- 生成中に届いた user の発言は保存しますが、生成中の応答には含めません。生成中の応答はそのまま返して保存します。
  応答の終わりに、まだ応答していない user の発言があるかを返し、クライアントは必要なら続けて応答を要求します。
- assistant の発言は、生成が最後まで終わったときだけ保存します。失敗・中断・切断では保存しません。
- API の具体的な形（経路名、SSE の event）は実装の Issue で決め、[履歴 API](../history-api.md) に記載します。

### 3. 会話の一覧と再開

- 会話の一覧は最終活動日時の新しい順に返します。
- クライアントは、起動時に一覧の先頭（最後にやり取りした会話）を開きます。会話がなければ新しく作ります。
- 会話の名前の変更・アーカイブは MVP の範囲外です。

### 4. 削除

- ユーザーは会話を削除できます。削除すると、その会話の発言と、その会話を出典にする長期記憶用のデータを同時に削除します。
  削除が確定した後に、生成中の応答や再送で会話を復活させません。
- 発言単位・往復単位の削除は MVP の範囲外です。
- AI の判断では削除しません。

### 5. 長期記憶との関係

- 保存した発言は、長期記憶を作るときの材料（出典）になります。出典は「会話 ID ＋ 発言の seq」で指します。
- 長期記憶の形成と、その privacy の判定（ADR 0005・0017）は、この ADR では変えません。形成の側で判定します。

### 6. 既存のデータ

既存の会話履歴（往復単位の表）は、新しい形式へ移しません。既存のデータはテスト用です（2026-10-17 のユーザー回答「今ある往復はテスト用のため移行不要」）。

## 置き換える決定

承認された時点で、次に置換の注記を付けます（本文は書き換えません）。

- [ADR 0004](0004-conversation-history.md)：往復をまとめた保存、request ID と revision による排他、保存の policy の既定拒否。
- [ADR 0005](0005-privacy-boundaries.md)：会話履歴の保存の前の判定（保存の判定だけ。送信と記憶形成の境界は維持）。
- [ADR 0006](0006-conversation-memory-controls.md)：指定発話の記憶除外、プライベートモード、アーカイブ。
- [ADR 0007](0007-memory-provenance-and-revocation.md)：出典の形式（turn revision ＋ message index → 会話 ID ＋ seq）。
- [ADR 0019](0019-memory-correction-invalidation.md)：保存拒否の語の検出と確認、往復単位の削除。
- SPEC §2.1、[履歴 API](../history-api.md)、CONTEXT の該当する用語。

## 影響

- Epic #127 で進めている形成（[#208](https://github.com/FYuki/digital-souls-core/issues/208) の job の台帳、
  [#209](https://github.com/FYuki/digital-souls-core/issues/209) のスレッド範囲の抽出）は、往復単位の履歴を前提にしています。
  この ADR を採用する場合は、形成の出典と予約の起点を発言単位に合わせる必要があります。
  2026-10-17 のユーザー回答（「記憶形成系は一時中断で良い」）により、Epic #127 は MVP の間は中断し、再開時に発言単位へ合わせます。
- 保存の前の判定がなくなるため、秘密情報も会話履歴には残ります。削除はユーザーの操作で行います。
- プライベートモードがなくなるため、長期記憶に入れたくない会話は、会話の削除で対応します。
