# #341 意味記憶の実装・受入状況

2026-09-15時点。子Issueの受入は、会話・意味抽出にGemma 4 12bを設定した構成で確認した。
最新の失敗・制限を含む証跡は[残受入条件の検証](validation/semantic-memory-341-remaining-acceptance-2026-09-15.md)を参照。
GitHub統合・CI・CodeRabbitレビューはPR #409 / #405の現在状態を正本とする。mainへのマージはユーザーが行う。

## 実装と検証

- Episode/Factと独立した共通Semantic正本、出典・版・所有・privacy検証、Chroma/outboxを実装。
- 前回正常処理以降のユーザー発言から増分取得し、訂正・時間変化・固定属性矛盾・自己申告優先を扱う。
- 自己申告からの直接取得だけをUI訂正できる。元会話を変更せずMANUAL根拠と履歴を保持する。
- 選択レコードの全版本文を削除し、同じ出典/版からの復活を防ぐ。元会話・Episodeを保持し、新しい根拠は別候補として受理する。
- 一般化と自己申告は正本で共存でき、検索・応答では現在の自己申告を優先する。
- 会話開始時に進行中の抽出を中断し、未処理予約から再試行する。Provider/Model/予算/timeout/optionsを用途別に変更できる。
- 実会話、実SQLite/Chroma/nomic、別会話応答、実UI訂正/直接取得・一般化の削除、失効、越境、再起動回復を確認。
- v6固定100件×両モデル各3回では12bのみ合格。実会話で発見した出来事の誤採用に4件を事前固定し、
  semantic-v9は104件×3回すべて各分類90%以上・禁止保存/越境0件。元100件の入力・期待値は不変。

## 設定と限界

最終受入では会話と意味抽出を12b、privacyとEpisodeをe4bとし、同一モデルの総contextを36,864に揃えた。
この構成の1標本は会話送信後70.5msで抽出中断、応答1.332秒、再試行後の未処理・index待ち0件。
設定例と制限は[推論運用](inference-operations.md)に記載する。

e4b会話では、複数経験と人格を含む今回の文脈で、取得済み自己申告を回答できなかった。
一般化の出典表現にも制限があり、自由文応答全般の品質を保証しない。
元の訂正関係をたどる別レコードの一括削除、#100の一般化/内省生成、外部活動学習、dogfood配備は対象外。

先行の調整・正式比較・実接続・CodeRabbit修正は[先行記録](validation/semantic-memory-341-2026-09-15.md)に保持する。
