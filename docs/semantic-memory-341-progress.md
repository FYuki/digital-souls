# #341 意味記憶の管理と実モデル調整記録

2026-09-15時点。これは途中の実装・調整証跡であり、Epic完了またはモデル採用の証明ではない。

## 実装

- 自己申告から直接取得した意味記憶だけを、値の入力でUI訂正できる。形成経路・所有者・自己申告フラグはAPIで変更させない。
- UI訂正はMANUAL根拠を持つ新しい意味記憶として記録する。元会話を改変せず、旧知識とのCORRECT関係、出典版、適用時期を監査画面で追える。
- 版の競合は409、許可されない訂正・privacy拒否は本文を含まない422となる。同じ要求の再送は同じ結果を返し、キーを違う訂正内容に再利用できない。
- 個別レコードの削除はその全版の本文を消し、同じ出典・版による復活を抑止する。元の会話とEpisodeを保持する。
- CORRECT関係でつながる別レコードまで一括削除する拡張は、削除範囲の回答待ちで未実装。
- LLMが一般化に対してCORRECTを提案しても、直接の自己申告を理由に一般化を停止させない契約を保存側でも保証する。

## モデル判断の修正

固定ケースのSHA256は `1603788df455b6598ab328468c9fe048692efce51c851b87ab0749efc6fdd676` のまま変更していない。

semantic-v3の診断では、会話文脈を保存済み知識と取り違え、存在しないtargetを返す問題が判明した。
semantic-v4はNEWと更新操作の組合せをJSON schemaで制約し、更新先を同じキャラクターの提示済みIDに限定する。
明示訂正、固定属性の矛盾、時間変化、自己申告優先の判定順を共通promptへ明記した。

privacy方針は2026-09-semantic-v1、分類promptはsemantic-privacy-prompt-v12。
「保存禁止」「記憶に残さないで」等の保存拒否表現を追加した。
合意要件で保存対象となる誕生日の月日、概括的な居住地域、好みを、それだけでOTHER_SENSITIVEとしないよう分類指示を明確化した。
正確な住所・連絡先・健康・金融・非公開の第三者情報などの拒否条件と、原発言全体・全slotの検査は保持する。
既存privacy固定fixtureはpolicy_versionのみ更新し、期待する分類や根拠範囲は変更していない。
共通privacyの実モデルconformanceは専用Ollamaのe4bで実施した。ADMISSION/QUERY_GATE各60ケース、
判定保留・偽陰性・偽陽性はともに0件。証跡は`/tmp/privacy-eval-i4psfe0z`。
