# 意味記憶の訂正・時間変化・矛盾と所有境界 (2026-09)

## 状態

ACTIVE。2026-09-14の#341要件整理で採用した判断。実装・実受入の完了を意味しない。
意味記憶の時間変化・矛盾・UI操作について本ADRを優先し、
[Episode・Fact・Semantic境界](episode-fact-semantic-boundaries-2026-09.md)のprivacy、出典失効、
SQLite正本、キャラクター境界は維持する。用語の入口は[用語集](../../CONTEXT.md)。

## 背景と選択肢

知識を最新発言で常に上書きすると過去の正しい状態やキャラクターが経験から得た見方が失われる。
全ての食い違いを保留すると、居住地など通常の変化にも確認が必要になる。
スレッドごとに知識を分離すると別スレッドで訂正・想起できない。
削除時に元経験まで削除すると経験と知識の責務を混同し、元経験を残して無制限に再抽出すると削除が無効になる。

## 決定

1. Episodeは本人の経験、Factは経験内の事実・申告、意味記憶は経験を離れて使える汎用知識・事実とする。
2. スレッドは増分抽出の枠に限定し、知識の照合・参照・訂正は同一character全体へ適用する。
3. 明示訂正は旧知識の訂正として追跡する。それ以外は原則時間変化とし、旧状態を履歴として保持する。不明な適用日時は補完しない。
4. 誕生日など通常変化しない属性は例外として矛盾保留し、どちらも確定して断定しない。
5. 自己申告と経験由来の一般化の食い違いは共存させ、会話では自己申告を優先する。矛盾だけでは一般化を無効にしない。根拠自体の失効は従来どおり停止・再評価する。
6. UI本文訂正はユーザー自己申告由来のみ。元発言改変ではなくUI訂正として根拠・版を追跡する。
7. UI削除は全形成経路に許可し、元会話・Episode削除と分ける。同じ出典・版からの復活を防ぎ、新たな根拠からの取得は許可する。削除済み本文を監査目的で保持し続けない。
8. 未解決矛盾を後続内省が参照できるようにするが、質問や主観表出は今回のMVPで実装しない。
9. 直接抽出は保存済み会話のユーザー発言を根拠にする。assistant発言のみから確定しない。外部活動からの学習は別Epic。
10. 推論は用途別に差し替え可能とし、通常会話を優先する。高負荷時は未処理を保持して抽出を遅延させる。

## 影響

適用時期と保存時刻を区別し、訂正・時間変化・矛盾関係を追跡する必要がある。
検索は本文類似度だけで決めず、SQLiteと根拠の現在版・状態、自己申告優先を確認する。
削除の再処理防止には本文を残さない最小の識別情報が必要となる。
一般化の再評価は#100へ委ね、#341で一般化推論を再実装しない。
性能・実接続の受け入れ条件は[実行指示書](../epic-341-semantic-memory-requirements.md)へ分離する。

## 既存の嗜好抽出との起動境界

`semantic-extraction` Targetが有効な場合、会話通知は汎用Semantic workerとEpisode workerへ渡す。
同じ自己申告を旧`USER_PREFERENCE` / `INTERACTION_PREFERENCE`へ新規に二重形成するschedulerは起動しない。
両方を起動すると、Semantic UIで訂正・削除した値が別正本から通常会話へ残るため、この案は採用しない。
Targetが無効な構成では既存の嗜好schedulerへフォールバックする。
#345のschema移行は既存レコードを保持して新しいSemantic用tableを追加する非破壊の更新である。
既存の保存済みpreferenceを削除・変換する移行は行わない。旧preferenceは旧契約のまま管理・検索する。
この記載は旧列の変換作業が#345に残っているという意味ではない。
形成型が別契約であることは維持し、旧preferenceを`SemanticRecord`と同一形式として扱わない。
