# 音声会話判断のBackend集約と一括移行（2026-09）

## 状態・適用範囲

**ACTIVE**。#358と2026-09-14〜15の対話で採用した設計判断。BE VADへの移設は未実装・未受入。
要件は[指示書](../epic-358-voice-backend-requirements.md)、用語は[用語集](../glossary.md)、進捗は[#358](https://github.com/FYuki/digital-souls/issues/358)で管理する。

新しいLiveKit音声入力経路のVAD・正式発話境界の決定権と互換性について、
[旧音声契約](voice-session-contract-2026-08.md)、
[Speech/Text契約](conversation-session-text-input-2026-09.md)、
[共通client契約](conversation-session-client-2026-09.md)のFE発話検知を前提とする記述より優先する。
実装前の旧経路と旧WebSocket baseline、変更対象外のsession／response／playback終端、
Speech/Textの優先、privacy、履歴保存は各既存契約を維持する。過去の実装・受入記録は書き換えない。

## 背景

既存FEはVADと発話区間を決定し、BEへspeechイベントを送る。一方、相槌／take-turn、
STT、LLM、TTS、取消・履歴は既にBEが扱う。Web／Desktopに発話判断を重複させると、
client更新・検出設定・端末差により同じ会話でも結果が分かれ、取消対象と状態の整合が難しくなる。

BEへ移すだけではSTT／LLM／TTSの待ち時間は解消しない。これは責務の整理であり、
モデル置換、相槌分類器の刷新、品質改善全体を同時に行う決定ではない。

## 決定

1. 認証済み連続PCMからBEが音声活動、発話区間、正式utteranceと入力世代を所有する。
   音声活動・STT確定・発言権判断・応答開始は別段階とし、既存Coreへ接続する。
2. FEはマイク取得・権限・mute・focus等の即時抑止、再生制御、端末／transport／実再生観測を所有する。
   FE VADを補助表示・計測に使っても正式入力の成立に依存させない。
3. 音声割り込みはBEのtake-turnで決定する。FEは通知された対象の再生をprovider取消完了より先に止める。
   明示的な同一Sessionへのtext submitは既存どおり即時local stopする。
4. FE／BEを一組で更新・切り戻しし、旧client互換期間を設けない。
   更新時の会話終了とブラウザ再読み込みを許容する。非対応clientはbootstrapで拒否し、FE判定へ暗黙fallbackしない。
   Core protocolとLiveKit private frameのversionを分け、具体的番号と移行手順はM1で確定する。
5. 通常の到着遅延を発話終了とせず、復元不能な音声欠落があった発話は破棄して話し直しを案内する。
   欠けた発話に属する遅延STT／previewも採用しない。判定方法・閾値の詳細は実行側へ委ねる。
6. 既存の会話入力・履歴・privacy・TTS選択契約を保持し、現在の機能状態と移設後の設計状態を分けて記録する。

## 検討した代替案と理由

| 選択肢 | 利点 | 採用しない理由・トレードオフ |
|---|---|---|
| FEの発話判断を維持し共通ライブラリだけ共有する | BEの連続音声処理を追加せず、端末で検出できる | client依存の正式判断と状態所有の分散が残り、BEを正本にする目的を満たさない |
| 新旧LiveKit clientの互換期間を設ける | 更新時に旧clientを残せる | FE／BEの複数判断経路を保守・検証する負担が増す。一括更新・会話終了をユーザーが許容したため採用しない |
| 復元不能な欠落音声でも認識結果を採用する | 話し直しを減らせる | 欠けた音声で意図と異なる回答や操作を始めるおそれがある。話し直しの負担を許容して破棄する |
| FEが音声検出直後に先行pauseしBE判断後に再開する | 停止反応を早められる | 相槌でも再生が途切れる新UXになる。既存のBE判断後停止を維持する |

## 影響

BEにはsession単位のモデル状態・buffer・readiness・負荷上限管理が必要になる。
送信者検証、schema生成物、入力世代、取消と実再生の対応、計測起点、共通clientを整合させる。
一括更新は会話の継続性を一時的に失うため、会話終了・再読み込み・履歴保持・版をそろえた切り戻しの手順を残す。
復元不能な音声欠落では利用者の再発話が必要になる。

移設前後の遅延回帰と既存未達を分ける定量的な受入基準は[指示書](../epic-358-voice-backend-requirements.md)を参照する。
#150の性能目標を緩和せず、#350の許容済み未達を今回の移設成功で解消済みにしない。
