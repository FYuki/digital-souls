# 文書の正本と更新責務（2026-09）

## 状態・適用範囲

**ACTIVE**。2026-09-28のアーキテクチャ見直しで合意した文書運用の判断。
対象はリポジトリ内の全文書（README、AGENTS、CONTEXT、`docs/`、ADR、受入記録）。
[リポジトリ運用方針](../repository-policy.md)と[ADR案内](README.md)の文書責務・状態の記述より優先する。

## 決定時点の前提

- READMEの「現在の実装範囲」、ADRの状態欄、`decisions/README.md`の優先関係一覧に、
  実装・受入の進捗（「未実装・未受入」「作業ブランチ」等）が書かれていた。
- Issueのクローズ後もこれらの記述が更新されず、実態と食い違っていた
  （例：#358・#424のクローズ後も`voice-backend-authority`が「未実装・未受入」のまま）。
- README・AGENTS・`system-architecture.md`に技術スタック、構成、実装範囲が重複していた。

## 決定

1. **1つの事実の正本は1か所に置く。** 他の文書は要約を複製せず、正本へリンクする。
2. **ADRは決定時点の記録とし、後から実装状況で書き換えない。**
   - 状態欄には判断の有効性（`ACTIVE`／`ARCHIVED`）と適用範囲・優先関係だけを書く。
   - 背景には決定時点の前提（改修前の状態）を書く。日付を明記し、現在形の進捗として書かない。
   - 実装・受入の進捗、ブランチ名、未完了の残課題はADRへ書かない。Issueへ書く。
   - 判断を変える場合は新しいADRを作り、置き換える範囲を明記する。旧ADRは全面失効時に`archive/`へ移す。
     一部置換の場合は旧ADRを書き換えず、[ADR案内](README.md)の優先関係に記載する。
   - 誤記・リンク切れ・誤った進捗記述の削除は、判断の変更ではないため旧ADRを直接修正してよい。
3. **READMEは人向けの概要と導入に限定する。** 目的、全体像、起動手順、文書への案内だけを書き、
   機能ごとの実装範囲や進捗は書かない。
4. **AGENTS.mdはエージェント向けの作業規約に限定する。** 技術スタック・リポジトリ構成は正本文書へリンクする。

| 情報 | 正本 |
|---|---|
| 目的・概要・導入 | README |
| 現在の構成・責務境界・runtime挙動 | [`system-architecture.md`](../system-architecture.md)とコード |
| 判断・決定時点の前提・不変条件 | ADR |
| 進捗・完了条件・受入結果 | GitHub Issues |
| 日付付きの実行結果・証跡 | `docs/validation/`等の受入記録（上書きしない） |
| 用語・実装名の対応 | [`CONTEXT.md`](../../CONTEXT.md) |
| 作業規約 | AGENTS.md、[リポジトリ運用方針](../repository-policy.md) |

## 採らなかった案

| 案 | 採らない理由 |
|---|---|
| ADRの状態に`IMPLEMENTED`等の実装状態を追加する | 状態の更新漏れが再発し、Issueとの二重管理になる |
| ADRの状態値をproposed／accepted／superseded（Nygard形式）へ置き換える | 既存ADRを一括改名する効果が小さい。`ACTIVE`はaccepted、`ARCHIVED`はsupersededに相当する |

## 影響

- 既存ADR・`decisions/README.md`の進捗記述を削除し、Issueへのリンクに置き換える。
- READMEの「現在の実装範囲」と音声Epicの進捗記述を削除し、アーキテクチャへの案内に置き換える。
- 実装状態の確認は、Issueとコード（`system-architecture.md`）で行う。
